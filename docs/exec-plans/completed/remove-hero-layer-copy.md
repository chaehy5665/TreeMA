# Remove Hero Layer Copy

## Purpose

Record the shipped change that removes the top hero layer and replaces layer-oriented copy with workspace-oriented wording.

## Canonical For

- The implementation intent behind removing the hero banner
- Validation and risk notes for the shipped copy and terminology cleanup

## Not Canonical For

- General product scope outside this UI and copy adjustment
- Detailed UI copy that remains defined in running code

## Summary

- Change: Remove the top hero banner, drop the `Project State Externalization Layer` and `KOJP Dashboard` copy, and replace remaining visible `state layer` wording with `workspace` wording.
- Goal: Simplify the workspace shell and remove branding or layer terminology that no longer matches the current product direction.
- Current state: The main panel now starts directly with the workspace canvas, settings no longer expose a hero toggle, and sample workspace naming is neutralized.

## Key Changes

- Product or workflow: Users land directly in the main workspace canvas without a separate hero summary band.
- Code or contract: Removed hero DOM, styles, and UI settings wiring; updated sample state naming and on-disk workspace copy to use workspace terminology.
- Docs or workspace: Updated `docs/TREEMA_WORKSPACE.md` to describe `.treema` as a workspace rather than a layer.

## Interfaces And Contracts

- Public API or CLI impact: None.
- Workspace file impact: New `.treema/README.md` content generated by `scripts/lib/treema-workspace.mjs` now refers to a workspace instead of a layer.
- Data model impact: None.

## Validation

- Commands to run: `npm run validate`
- Manual scenarios to verify: Open the app, confirm the hero banner is absent, open Settings and confirm there is no hero toggle, then load the sample state and verify KOJP branding is gone from visible copy.

## Assumptions And Risks

- Assumptions: The top hero summary cards were decorative and not required for core navigation or operations.
- Risks: Users lose at-a-glance aggregate metrics on first load, so summary cards may need to return in a different surface if that overview proves necessary.
